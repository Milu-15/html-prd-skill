## 1. 通用三栏结构

静态 HTML 需求页面默认由左侧导航、中间工作区和右侧需求说明组成。支持拖动分隔线时，保证三栏都有稳定最小宽度；窄屏可以隐藏辅助栏，但不得让正文或原型横向溢出。

内置模板在宽度小于 1132px 时切换为窄屏布局；桌面分栏拖动需同时保留导航、工作区和说明区的最小宽度，窗口缩小时重新约束列宽。

沿用现有项目时，不强制替换三栏比例、设计系统或导航实现。

新项目使用中性低保真样式，将品牌、颜色、字号和组件规则写入项目设计规范，不在全局 skill 中写死特定产品视觉。

### 左侧导航格式

- 顶部标题使用当前整份需求的名称，不随当前页面切换；页面名称显示在对应导航项及右侧正文。
- 导航按业务模块或需求主题分组，组内列出对应的需求页面。分组名大于页面项字号并加粗；内置模板采用需求标题 20px、分组名 16px、页面项 14px。
- 同一份需求的各页面保持相同的分组、页面清单和顺序，页面项链接到真实文件；当前项高亮并标记 `aria-current="page"`。分组标题不充当虚假的页面链接。
- 底部显示整份需求的“创建时间”和“更新时间”，默认格式 `YYYY-MM-DD`。创建时间为首次创建该需求的日期，后续不得改写；更新时间为最近一次实际修改该需求的日期。多页面保持两项时间一致，新增页面不重置需求创建时间。
- 时间静态写入 HTML，不使用打开页面时的当前日期冒充更新时间。沿用已有项目时以已有记录为准，缺少可信日期则标注“待确认”，不推测历史时间。
- 标题在顶部、时间在底部，分组列表占据中间剩余空间并独立滚动；长标题或长页面名换行，不遮挡底部时间。
- 窄屏沿用现有的隐藏辅助栏策略，不改变其他区域布局。

### 中间原型区：展示结构

仅在“原型 + 需求说明”模式使用以下两层结构。统一的是原型展示方式与外框，不是产品页面内部布局。

```text
中间原型区
├─ 顶部说明与演示工具栏
│  ├─ 左侧：当前页面名称 + 简短说明
│  └─ 右侧：场景／状态切换（按需）
└─ 原型展示画布
   └─ 手机端或网页端的页面外框
```

- 不额外添加“原型说明”提示块、横幅或演示限制声明；这不影响页面标题、简短用途说明和必要的状态切换，也不删除产品内正常业务提示。原型未实现范围与验证限制写到交付说明或验收记录中。
- 工具栏属于需求评审界面，位于产品外框之外，不混入正式产品 UI。左侧标题与当前导航页面一致，下方简述页面用途或核心操作，不使用整份需求标题代替页面名称。
- 有多个需要评审的场景时，在右侧使用分段按钮等轻量控件，明确标识当前选中项；切换后呈现对应内容及交互，不仅改变按钮样式。没有多状态时不展示切换控件，不虚构场景。空间不足时允许工具栏换行，不遮挡原型。
- 画布使用中性浅色背景，原型水平居中、靠上排列，与工具栏保持适当间距。以细边框或轻微阴影区分页面与画布，不增加复杂装饰。
- 长内容在原型容器内部滚动，不无限拉长外框。预览缩放保持宽高比例，不因需求文档栏宽变化而擅自重排产品页面。
- 不统一规定页面内部的导航栏、系统状态栏、步骤条、卡片、表单、底部按钮、安全区或业务配色。具体结构、组件和交互由页面需求、目标平台及项目设计规范决定。

## 2. App 模式

### 原型 + 需求说明

- 外框采用竖向手机视口比例，同一项目保持统一基准宽高。优先使用项目现有尺寸；无既有规范时默认 375 × 812px。
- 使用简洁矩形、细边框或轻微阴影，可使用小圆角；不强制添加写实机身、刘海、摄像头或侧边按键。
- 外部栏宽变化时不任意拉伸手机页面；空间不足时优先适配外围布局，必要时等比缩小预览，保持内部基准尺寸与比例。
- 保留真实入口、弹层、Toast、返回和异常恢复交互。
- 检查常用移动视口，保证吸底操作、长文案、弹层和键盘场景不遮挡。

### 仅需求说明

- 中间工作区保持空白，不显示手机框、示意按钮或状态切换。
- 右侧全新页面显示九段式章节大标题和章节序号，并写完整逻辑；仅页面修改类型直接列修改项，不显示章节大标题和章节序号。
- 不因没有原型而省略业务规则、异常和验收口径。

## 3. Web 模式

### 原型 + 需求说明

- 外框采用横向桌面网页视口，不套手机外框。同一项目统一桌面基准尺寸，优先遵循已有设计规范；内置模板以 1200 × 760px 作为可调整的起点，不将其强加给已有项目。
- 使用简洁矩形边界、细边框或轻微阴影，不强制添加浏览器地址栏、标签栏等装饰。
- 在画布可用空间内合理展示，固定桌面尺寸可等比缩小预览。外部预览缩放与产品响应式行为分开处理；只有需求明确要求响应式时，才按产品规则调整内部布局。
- 工具型后台优先保证扫描、对比和重复操作效率，不使用营销页式布局。

### 仅需求说明

- 中间工作区保持空白，不创建占位后台页面。
- 右侧说明 Web 页面结构、操作和状态，但不将说明伪装成已完成原型。

## 4. 仅需求说明模式

仅需求说明不是“少写需求”，而是不制作中间可交互页面。适用于：

- 需求仍在梳理，视觉方案尚未开始。
- 只补充业务规则、状态机制或跨页面口径。
- 用户明确要求不做原型。

禁止为了填满中间栏而生成低质量占位 UI。模板中的中间区必须保持空白，不生成顶部说明工具栏、状态切换、设备／网页外框或占位原型。

## 5. 模板使用

运行 `scripts/scaffold_page.mjs` 选择平台、交付模式及页面需求类型：

```bash
node scripts/scaffold_page.mjs \
  --output /absolute/path/page.html \
  --platform app|web \
  --mode prototype|requirements \
  --document page \
  --page-type new|change \
  --title "页面名称" \
  --project-title "当前需求标题"
```

`--title` 是当前页面名称，`--project-title` 是整份需求的标题；单页需求省略后者时沿用页面名称。脚手架先生成一个“需求页面”分组，随后按真实业务模块补齐分组和页面链接，不添加不存在的页面。

新需求的创建时间和更新时间默认为脚手架运行环境的本地日期，并静态写入。向已有需求新增页面时，传入 `--created-at YYYY-MM-DD --updated-at YYYY-MM-DD` 复用需求级日期；若运行环境时区与用户时区不同，也需显式传入用户时区的日期。不要通过重跑脚手架更新既有页面。

模板由以下资源组合：

- `assets/page-shell.html`：三栏、拖动和响应式外壳。
- `assets/middle-app.html`：App 手机工作区。
- `assets/middle-web.html`：Web 页面工作区。
- `assets/middle-empty.html`：无原型的空白工作区。
- `assets/spec-page.html`：全新页面的精简九段式占位结构。
- `assets/spec-page-change.html`：页面修改标识、变更摘要与修改项列表；按实际变更填写列表，不展示章节标题或输出未变更声明。

`--page-type` 默认 `new`，仅用于 `--document page`；`change` 的草稿须补入至少一个真实修改项后才能通过严格检查。

旧的 `--document rules|overview` 与对应 `spec-rules.html`、`spec-overview.html` 仅保留兼容，不作为右侧说明的新规范；独立文档按项目或用户约定编写。

原型模板提供外部页面标题、待补充的用途说明、画布与空的产品容器，不预置业务结构或虚假的状态切换。按实际页面补齐说明、原型和必要的状态控件。外框尺寸由 `.app-frame` / `.web-frame` 定义，预览脚本按画布宽度等比缩小，不改写内部尺寸；若产品需要真正响应式，应按项目目标视口另行实现和验收，而不是把 CSS 预览缩放当作响应式验证。

生成后立即替换占位内容。成熟项目只参考结构，不运行脚手架覆盖现有页面。
